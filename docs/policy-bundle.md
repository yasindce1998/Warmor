# Policy Bundle (OCI)

`warmor-policy-bundle` packages compiled `.wasm` policies as OCI artifacts and pushes/pulls them to/from container registries. This enables versioned policy distribution using the same infrastructure as container images.

## Installation

```bash
make build-policy-bundle
```

## Usage

Bundles are signed with an ed25519 key on push and verified on pull. Pull
fails closed: without `--verify-key` (or the explicit `--insecure-skip-verify`
opt-out) nothing is downloaded, and a missing or invalid signature is an
error.

### Generate a signing key pair

```bash
warmor-policy-bundle --keygen --sign-key signing.key --verify-key signing.pub
```

`signing.key` is a PKCS#8 PEM private key (written with mode 0600); keep it in
your CI secret store. `signing.pub` is a PKIX PEM public key; distribute it to
every node that pulls policies. Existing files are never overwritten. Keys
generated by `warmorctl` (Certs → "Generate policy signing key pair") use the
same format.

### Push a policy to a registry

```bash
warmor-policy-bundle --push \
  --ref ghcr.io/myorg/warmor-policies/nginx:v1.0.0 \
  --wasm policy.wasm \
  --sign-key signing.key \
  --name nginx-hardening \
  --policy-version 1.0.0 \
  --description "Nginx container hardening policy"
```

Push prints the manifest digest, which can be used to pin pulls.

### Pull a policy from a registry

```bash
warmor-policy-bundle --pull \
  --ref ghcr.io/myorg/warmor-policies/nginx:v1.0.0 \
  --wasm ./downloaded-policy.wasm \
  --verify-key signing.pub

# Pin to an exact manifest digest (recommended for deployments)
warmor-policy-bundle --pull \
  --ref ghcr.io/myorg/warmor-policies/nginx@sha256:<digest> \
  --wasm ./downloaded-policy.wasm \
  --verify-key signing.pub
```

The output file is written atomically and only after every check passes; on
failure an existing file at `--wasm` is left untouched.

## Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--push` | — | Push a .wasm policy to the registry |
| `--pull` | — | Pull a .wasm policy from the registry |
| `--ref` | required | OCI reference (e.g., `ghcr.io/org/policy:tag`) |
| `--wasm` | required | Path to .wasm file (input for push, output for pull) |
| `--name` | `warmor-policy` | Policy name stored in artifact metadata |
| `--policy-version` | `1.0.0` | Policy version stored in artifact metadata |
| `--description` | — | Policy description stored in artifact metadata |
| `--keygen` | — | Generate a key pair at `--sign-key` / `--verify-key` and exit |
| `--sign-key` | required for push | ed25519 private key PEM used to sign on push |
| `--verify-key` | required for pull | ed25519 public key PEM used to verify on pull |
| `--allow-unsigned` | `false` | Push without a signature (INSECURE) |
| `--insecure-skip-verify` | `false` | Pull without verifying the signature (INSECURE). If `--verify-key` is also given, the signature is still checked |
| `--max-wasm-size` | `67108864` (64 MiB) | Largest wasm layer accepted on pull |
| `--version` | — | Print tool version and exit |

## OCI Artifact Structure

The bundle uses standard OCI image manifest format:

- **Config**: `application/vnd.warmor.policy.config.v1+json` — JSON with policy name, version, description
- **Layer**: `application/vnd.warmor.policy.wasm.v1` — The compiled .wasm policy binary
- **Annotation** `org.warmor.policy.signature` — base64 ed25519 signature (see below)
- **Annotation** `org.warmor.policy.signature.keyid` — hex SHA-256 of the signer's PKIX public key (informational only; used in error messages)

### Signature

The signature lives in the manifest annotations, so it travels with the
manifest through any OCI registry without needing the referrers API. Because a
manifest cannot contain a signature over its own digest, the signature covers
the content-addressed descriptors the manifest references: the deterministic
JSON

```json
{"schema":"warmor.policy.bundle.signature.v1",
 "config":{"mediaType":"...","digest":"sha256:...","size":N},
 "layers":[{"mediaType":"...","digest":"sha256:...","size":N}, ...]}
```

Since every blob is fetched and checked against its digest, the signature
transitively authenticates the wasm and config contents. Other manifest
annotations (title, name) are not signed and are informational.

A signature binds content, not a tag: a registry could serve an older bundle
that was signed with the same key under a newer tag. Pin deployments by digest
(`ref@sha256:...`) to rule out rollback, and use distinct keys for
policies that must not be interchangeable.

### Pull checks

Before downloading any blob, Pull requires:

- the manifest to be an OCI image manifest (`application/vnd.oci.image.manifest.v1+json`), at most 1 MiB, and to match the pinned digest if one was given;
- `artifactType` to be empty or the config media type, and the config media type to be `application/vnd.warmor.policy.config.v1+json`, at most 1 MiB;
- exactly one wasm layer, at most `--max-wasm-size` bytes;
- a valid signature from `--verify-key` (unless `--insecure-skip-verify`).

The config must also decode as JSON, and every blob must match its digest and
size.

## Authentication

The tool uses the standard Docker/OCI credential chain:
- `~/.docker/config.json` (Docker login)
- Environment variables (`REGISTRY_TOKEN`, etc.)
- Platform-specific credential helpers

For GitHub Container Registry:
```bash
echo $GITHUB_TOKEN | docker login ghcr.io -u USERNAME --password-stdin
```

## Typical Workflow

```bash
# 1. Generate and merge policies
warmor-sbom-policy --rootfs ./rootfs sbom.json -o sbom-policy.yaml
warmor-policy-gen audit.ndjson -o audit-policy.yaml
warmor-policy-merge --validate sbom-policy.yaml audit-policy.yaml -o merged.yaml

# 2. Compile to wasm
warmor-compile merged.yaml -o policy.wasm

# 3. Sign and push to registry
warmor-policy-bundle --push \
  --ref ghcr.io/myorg/warmor-policies/myapp:v1.0.0 \
  --wasm policy.wasm \
  --sign-key signing.key \
  --name myapp-policy \
  --policy-version 1.0.0

# 4. Pull and verify on deployment nodes
warmor-policy-bundle --pull \
  --ref ghcr.io/myorg/warmor-policies/myapp@sha256:<digest> \
  --wasm /etc/warmor/policy.wasm \
  --verify-key /etc/warmor/signing.pub

# 5. Enforce
sudo warmor-daemon --policy /etc/warmor/policy.wasm
```

## CI/CD Integration

In a GitHub Actions workflow:
```yaml
- name: Bundle and push policy
  run: |
    warmor-policy-bundle --push \
      --ref ghcr.io/${{ github.repository }}/policy:${{ github.sha }} \
      --wasm policy.wasm \
      --sign-key "$RUNNER_TEMP/signing.key" \
      --name "${{ github.repository }}-policy" \
      --policy-version "${{ github.ref_name }}"
```
